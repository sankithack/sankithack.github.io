What the source shows

  • This PAL and LLPC cannot target GFX9 (Vega). PAL's GfxIpLevel starts at GfxIp10_1 and LLPC asserts gfxIp.major >= 10, so the site covers GFX10, 11 and 12.
  • PAL's hw/gfxip/gfx9 directory is the GFX10 to 11.5 hardware layer. Device creation sends those generations to Gfx9::CreateDevice.
  • Reserving GPU address space never reaches the kernel. libdrm's amdgpu_va_range_alloc is a user-space allocator; the kernel first sees the address when a BO is mapped there.
  • Every VkDeviceMemory is resident for its whole life. XGL registers each allocation as a device-global reference (Device::AddMemReference).
  • Shader modules are not compiled to ISA. Code generation happens per pipeline, because the compiler needs vertex formats, colour formats and the descriptor layout.

How to read a code panel

  • The header shows the repository, file and line range. Open at shows the full file at the pinned commit with those lines highlighted.
  • Excerpts are cut from the source by tools/build.py, never retyped, and are at most 30 lines, so they often stop mid-function.
  • Each panel ends with What this does in plain language. Where something could not be traced, the page says not traced rather than guessing.
  • Dotted underlines are glossary terms. Press / to search pages, steps and the whole code reference.
