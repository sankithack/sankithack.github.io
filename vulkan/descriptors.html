Descriptor sets

A descriptor set is a block of GPU memory full of hardware descriptors (SRDs). XGL writes those bytes from the CPU, puts the set's address into a few shader registers when you bind it, and the compiled shader loads descriptors from that address. This page follows one uniform buffer from layout to ISA.

The model in four sentences

  1. Layout: each binding gets a fixed size and offset inside the set's memory, from PAL's SRD sizes (DescriptorSetLayout::Create).
  2. Pool and allocation: a pool is one CPU-mapped GPU allocation, and allocating a set reserves a range of it.
  3. Update: writing a descriptor is a CPU store of 16 or 32 bytes into that range. No command, no ioctl.
  4. Bind and use: binding records the set's GPU address as user data. At draw time PAL writes it into the shader's user SGPRs, and the shader loads SRDs relative to it.

Step-through: layout → pool → update → bind → shader load

Build a buffer SRD

This is the descriptor vkUpdateDescriptorSets writes for a VK_DESCRIPTOR_TYPE_STORAGE_BUFFER on GFX10/11. The fields and constants are the ones PAL's CreateUntypedBufferViewSrds uses. Change the address, range or stride and watch the four DWORDs change.

Worked example: one uniform buffer, end to end

An application has a 256-byte uniform block at offset 512 of a buffer, bound as set 0, binding 0, and a fragment shader that reads it.

VkDescriptorSetLayoutBinding binding = {
    .binding = 0, .descriptorType = VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER,
    .descriptorCount = 1, .stageFlags = VK_SHADER_STAGE_FRAGMENT_BIT };
/* ... vkCreateDescriptorSetLayout, vkCreateDescriptorPool, vkAllocateDescriptorSets ... */
VkDescriptorBufferInfo info = { .buffer = ubo, .offset = 512, .range = 256 };
VkWriteDescriptorSet write = {
    .sType = VK_STRUCTURE_TYPE_WRITE_DESCRIPTOR_SET, .dstSet = set, .dstBinding = 0,
    .descriptorCount = 1, .descriptorType = VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER, .pBufferInfo = &info };
vkUpdateDescriptorSets(device, 1, &write, 0, NULL);
vkCmdBindDescriptorSets(cmd, VK_PIPELINE_BIND_POINT_GRAPHICS, layout, 0, 1, &set, 0, NULL);
vkCmdDraw(cmd, 3, 1, 0, 0);

What the driver does

  1. Layout: binding 0 is a uniform buffer, so its static size is untypedBufferView (a 16-byte BufferSrd on GFX10/11). The set's static section is 4 DWORDs.
  2. Allocate: the pool's bump allocator returns an aligned offset; the set's CPU and GPU addresses are the pool's base plus that offset.
  3. Update: WriteBufferInfoDescriptors computes gpuAddr = buffer VA + 512 and range 256, then PAL encodes the SRD straight into the set's memory. Put the buffer's address plus 512 into the SRD builder above, with range 256: DW2 is 0x00000100 and DW3 is the fixed raw-buffer pattern.
  4. Bind: the set's GPU address goes into setBindingData and, through CmdSetUserData, into PAL's user-data entries at the pipeline layout's setBindingRegBase. No PM4 is written yet.
  5. Draw: ValidateDraw finds the entries dirty and emits a SET_SH_REG that puts the pointer into the pixel shader's user SGPRs (WriteUserDataEntriesToSgprs), then the DRAW_INDEX_AUTO from Topic 4.
  6. Shader: when the pipeline was compiled, LGC's LowerDesc turned the uniform-block access into "load 4 DWORDs at (descriptor table pointer + binding offset)", using the resource mapping XGL built from the same pipeline layout (BuildPipelineResourceMapping).

Variations

  • VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER_DYNAMIC: takes no space in the set. At bind time XGL patches the dynamic offset into the SRD and puts the whole descriptor in user data, so changing the offset per draw needs no memory write.
  • Sampled image: the 32-byte ImageSrd was built at vkCreateImageView; the update is a memcpy.
  • Null descriptor: a VK_NULL_HANDLE view writes zeros. For buffers PAL also leaves DW3 = 0 when the address is 0 (try address 0 above).
  • Push constants: same user-data mechanism, without any memory at all.

Why pipelines depend on the pipeline layout

The compiled ISA hard-codes which SGPRs hold which set pointers and the offset of every binding. Both come from the VkPipelineLayout through the resource mapping. That's why a pipeline must be used with a compatible layout, and why changing the layout means compiling a new pipeline.

Generation differences

  • GFX12 has its own SRD encodings (sq_buf_rsrc_t and sq_img_rsrc_t in the gfx12 chip headers); the builder above shows the GFX10/11 layout.
  • The descriptor sizes an application sees through VK_EXT_descriptor_buffer are exactly PAL's srdSizes, so they can change with the generation.
