Sources, SHAs & status

Every code panel and source link on this site points at the commits below. Excerpts are cut from these checkouts by tools/build.py, and tools/verify.py checks every identifier and reference against them.

Pinned commits

The same table, with branch names and dates, is in src/VERSIONS.md. xgl, pal and llpc were cloned from branch dev, which AMDVLK's default.xml manifest pins; at clone time dev and master pointed to the same final commit. The LLVM fork is the manifest's amd-gfx-gpuopen-dev branch, sparse-checked-out to llvm/lib/Target/AMDGPU. Linux is a sparse checkout of drivers/gpu/drm/amd/amdgpu and include/uapi/drm.

Because libdrm and Linux are much newer than the frozen AMDVLK code, the kernel and libdrm line numbers match today's code, which may differ from the versions AMDVLK last shipped against. The interfaces used here (GEM create/VA/mmap, CS with chunks, syncobjs) are long-standing uAPI.

Not traced, or traced only to the entry point

  • Vulkan loader internals: the Khronos loader isn't in any cloned repo. Only the ICD interface XGL exports is shown.
  • PAL ValidateDraw register sequence: shown at the call site only.
  • LLVM AMDGPU instruction selection, register allocation and scheduling: entry points only (addPassesToEmitFile, AMDGPUAsmPrinter, PAL metadata).
  • gpurt (ray-tracing library), MetroHash and CWPack: listed in the manifest but not cloned. Ray-tracing pipelines are out of scope.
  • PAL's on-disk archive-file pipeline cache: mentioned only.
  • Kernel memory management (TTM placement and eviction, page-table updates, mmap fault path) and the GPU scheduler's internals: entry functions only.
  • GFX9 (Vega): support was removed from these sources, so there is nothing to trace.
  • Barrier-driven decompression blits (RPM) and image layout handling: not stepped through.

How this site was built and checked

  1. Read the code and wrote the call chains (PLAN.md).
  2. tools/spec.py describes each step by anchor text, not line number. tools/build.py finds the anchor in the source, cuts the excerpt (≤ 30 lines), checks that the listed symbols appear inside it, and builds a SHA-pinned permalink.
  3. tools/verify.py extracts every <code> identifier and every reference from the pages and the generated data, and checks each against the checkouts. It also checks internal links and anchors.
  4. A headless Chromium run clicks through the diagram, every stepper, search, the PM4 widget and dark mode.
