Use cases and driver settings

Concrete things you can do with this driver, each tied to the setting that enables it and the line of code that reads that setting. Every setting name below is checked against the settings files at the pinned commit.

How settings are applied

The AMDVLK README says to put one name,value pair per line in amdVulkanSettings.cfg or amdPalSettings.cfg, in /etc/amd or the directory named by $AMD_CONFIG_DIR. Lines starting with ; are comments, and settings are read only when a device is created, so restart the application after editing. Enum settings take the number shown in the code reference; bitmask settings take the sum of their bits.

Every XGL and PAL setting, with its type, default, allowed values and description, is in the settings tab.

The README is out of date in two places. It lists EnableVmAlwaysValid and AllowVkPipelineCachingToDisk, but neither name exists in any settings file at the pinned commits. Their entries below were replaced by the settings that do exist.

Debugging correctness

Find the submission that hangs or corrupts the GPU

When a GPU hang or corrupted frame can't be pinned to one command buffer.

WaitAfterSubmit,1

XGL then waits for the queue to go idle after every PAL submission. With multiSubmitChaining off, PalQueueSubmit also submits command buffers one at a time, so a hang shows up right after the offending one. Expect a large slowdown.

Setting: WaitAfterSubmit, MultiSubmitChaining. Read at: ,

The README also suggests IdleAfterSubmitGpuMask. It is defined in settings_core.json, but no source file in the pinned PAL reads its value, so it has no effect in this build.

Check whether a bug is a missing barrier

When rendering is wrong only sometimes, or only on some GPUs: a classic sign of a missing pipeline barrier.

DbgBarrierPostCmdEnable,0x8FFFFFFF

XGL inserts a full barrier after every command in the mask (DbgBarrierPostCmd runs after draws, dispatches, copies and so on). If the bug disappears, a barrier is missing. Narrow it down with the individual bits, e.g. DbgBarrierDrawIndexed = 2 or DbgBarrierDispatch = 8.

Setting: DbgBarrierPostCmdEnable. Read at:

The setting's own description says it requires a driver built with VKI_ENABLE_DEBUG_BARRIERS=1.

Rule out a residency or eviction bug

When a crash or corruption might be caused by memory being evicted or missing from a submission's BO list.

AlwaysResident,1

PAL creates every BO with AMDGPU_GEM_CREATE_NO_EVICT and stops building BO lists on submit (the alwaysResident checks in AllocateOrPinMemory and OsSubmit). If the problem goes away, look at memory residency (Topic 2).

Setting: AlwaysResident. Read at: ,

Zero new VRAM allocations (already the default here)

When results depend on stale memory contents.

InitializeVramToZero,1

XGL passes initializeToZero to PAL, which adds AMDGPU_GEM_CREATE_VRAM_CLEARED to VRAM allocations. The upstream kernel checked out here already sets that flag on every GEM create (its comment says "always clear VRAM"), so with this kernel new VRAM is zeroed either way and the setting changes nothing.

Setting: InitializeVramToZero (default true on Linux). Read at: , ,

Shaders and pipelines

Dump every pipeline, its SPIR-V and the compiled code

When a shader looks miscompiled, or you want the ISA of a hot pipeline.

EnablePipelineDump,1
PipelineDumpDir,spvPipeline

Every pipeline creation writes a .pipe file (the full Vkgc build info) and the SPIR-V of its shaders, named by pipeline hash. The README says the directory is relative to $AMD_DEBUG_DIR, $TMPDIR or /var/tmp. A .pipe file can be recompiled offline with LLPC's standalone amdllpc tool.

Settings: EnablePipelineDump, PipelineDumpDir. Read at: . See

Replace one shader without rebuilding the application

When you want to test a fix to a shader you can't easily rebuild.

ShaderReplaceMode,1
ShaderReplaceDir,ShaderReplace

With mode 1 (ShaderReplaceShaderHash), for a shader whose hash is AAA, a file shader_0xAAA_replace.spv in the replacement directory is used instead of the original SPIR-V. Other modes replace by pipeline hash (2, 3), by ISA (4), or both (5). Get the hashes from a pipeline dump first.

Settings: ShaderReplaceMode, ShaderReplaceDir. Read at:

Measure cold compile times or rule out a stale cache

When first-run stutter matters, or a bug might come from a cached binary.

ShaderCacheMode,0

Mode 0 (ShaderCacheDisable) stops XGL from giving LLPC its internal cache adapter, so caches 3 and 4 on the shaders page stay empty. Mode 2 (ShaderCacheEnableOnDisk) persists the cache to disk instead.

Setting: ShaderCacheMode. Read at:

Compare NGG against the legacy geometry path (GFX10 only)

When a geometry-heavy workload behaves differently than expected on GFX10.

EnableNgg,0

EnableNgg is a bitmask of pipeline types: VS/FS = 1, GS = 2, tessellation = 4, tessellation + GS = 8 (default 1 | 4). XGL sets nggState.enableNgg per pipeline from it. On GFX11 and later LGC enables NGG regardless (the shaders page).

Performance

Find out whether you are CPU-bound

When you need to know how fast the application would run with an infinitely fast GPU.

IFH,1

Infinitely Fast Hardware. With IfhModePal (1), PAL replaces every submitted command buffer with a dummy one, so the GPU does almost no work. If the frame rate hardly changes, the bottleneck is on the CPU. Mode 2 (IfhModeKmd) instead creates kernel contexts with AMDGPU_CTX_FLAGS_IFH; that flag comes from PAL's own extension header (amdgpu_drm_exts.h) and is not in the upstream kernel uAPI checked out here, so use mode 1 on upstream kernels.

Setting: IFH. Read at: ,

Time every draw on the GPU

When you need per-draw or per-command-buffer GPU timings without an external profiler.

GpuProfilerMode,1
GpuProfilerConfig.Granularity,0
GpuProfilerConfig.StartFrame,100
GpuProfilerConfig.FrameCount,1

PAL inserts its GpuProfiler layer between XGL and the core, which records timestamps around each command. Granularity 0 is per draw, 1 per command buffer, 2 per frame. The README describes the CSV output and a timingReport.py script that summarizes it. Modes 2 and 3 also capture thread traces.

Settings: GpuProfilerMode, GpuProfilerConfig.Granularity, GpuProfilerConfig.StartFrame, GpuProfilerConfig.FrameCount. Read at: . See

Watch frame times and memory per heap live

When you want an on-screen view of FPS, CPU and GPU frame time, and how much memory each heap holds.

DebugOverlayEnabled,1

PAL wraps its platform in the debug-overlay layer, which draws on presented images. The memory ledger maps directly onto the heaps on the memory page.

Setting: DebugOverlayEnabled. Read at: . See

Make CPU writes to GART memory write-combined

When an application maps a HOST_CACHED memory type only to stream data to the GPU.

OverrideHeapGartCacheableToUswc,1

XGL silently moves allocations from GpuHeapGartCacheable to GpuHeapGartUswc. CPU writes become write-combined and fast, but CPU reads from those mappings become very slow, so only use it for write-only uploads.

Setting: OverrideHeapGartCacheableToUswc. Read at:

Stop repeated map/unmap from costing mmap calls

When an application maps and unmaps the same memory every frame.

SkipUnMapMemory,1

XGL keeps the first CPU mapping and returns it on later vkMapMemory calls, avoiding a DRM_AMDGPU_GEM_MMAP plus mmap each time.

Use cases for learning the codebase

  • Answer "what does this Vulkan call do in the driver?" Find it in the entry-point table; its first call takes you to the XGL method, and the topic pages take it further down.
  • Answer "which ioctl does this end in?" The PAL → libdrm tab maps each libdrm function PAL calls to the ioctl its body issues and to the kernel handler.
  • Read an unfamiliar PM4 dump. Look up the opcode byte in the PM4 tab, then use the packet widget to decode a header.
  • Understand a compile-time difference between GPUs. The compiler passes tab shows which LGC passes are conditional on the GFX level.
